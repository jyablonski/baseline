# Features

One doc per user-facing feature: what users see, how it works, where it is served, its knobs, the invariants that must hold, gotchas, and what it deliberately does not do. Each starts with front matter (`summary`, `status: current | planned`, `code:` paths, `related:`), and the `code:` paths say which changes should touch it.

`python3 scripts/feature-docs.py for <path>` names the doc that covers a file. `check` (a pre-commit hook) fails when a `code:` or `related:` path no longer exists or the table below is out of date; `index` regenerates the table from the front matter. A second hook prints a reminder when a commit changes a feature's code without its doc.

A new feature gets a doc with the sections the others use (What users see, How it works, Surfaces, Knobs, Invariants, Gotchas, Out of scope); `social.md` keeps its older layout.
